## 2. 技术栈与框架选型

### 2.1 前端

| 项 | 选型 | 说明 |

| 框架 | React 18 + TypeScript | 生态成熟，React Flow 依赖 |

### 2.2 后端

## 3. 数据模型

### 3.1 数据库约定

- 一期统一使用 SQLite（WAL 模式 + busy_timeout），单实例部署；后续用户量增长再评估 MySQL 8
- 主键 `CHAR(36)` UUID；时间 `DATETIME(3)` UTC
- JSON 字段：SQLite 用 `TEXT`（JSON1 扩展支持 json 函数）
- 所有业务表含 `created_at` / `updated_at`；软删除表另有 `deleted_at`
- 状态用字符串枚举，便于迁移

### 3.4 画布 JSON 与执行模型

```json
{
  "schemaVersion": "1.0",
  "viewport": {"x": 0, "y": 0, "zoom": 1},
  "nodes": [{
    "id": "n1",
    "type": "PROJECT_SETUP",
    "position": {"x": 120, "y": 80},
    "data": {"name": "项目设定", "templateVersionId": "tv1", "config": {"overrides": {}}}
  }],
  "edges": [{
    "id": "e1",
    "source": "n1",
    "sourceHandle": "project_state",
    "target": "n2",
    "targetHandle": "project_state"
  }]
}
```

保存时后端把画布 JSON 规范化到 `nodes/edges` 表并保留原始 `canvas_json`；发布时从规范表生成 `workflow_versions.snapshot_json`。执行器只读取版本快照，不读取实时草稿。React Flow 的 `sourceHandle/targetHandle` 分别映射后端 `source_port/target_port`；位置、尺寸、分组仅用于 UI，不参与拓扑排序。`mapping_json` 负责从上游资产内容抽取字段，解析失败应在运行前校验阶段报错。

## 4. 存储方案（图片 / 视频 / 对象存储）

### 4.1 存储选型：阿里云 OSS

使用**阿里云 OSS 私有桶**（可复用现有 `renlg` 桶，或新建 `drama-studio` 专用桶）。

**为什么 OSS 而非本地磁盘 / 自建 MinIO：**
- 图片/视频是重资产（单镜视频几十 MB ~ 数百 MB），本地磁盘难扩展
- OSS 提供生命周期管理（自动清理临时文件）、CDN 加速（分发预览图/视频）、预签名 URL（安全访问私有对象）
- 现有经验：`oss_upload.py` 零依赖上传脚本、生命周期规则、签名 URL 均已有实践

### 4.2 桶与访问控制

| 项 | 配置 |
|---|---|
| 桶 | `drama-studio`（私有权限，读写走签名 URL） |
| 区域 | `oss-cn-hangzhou.aliyuncs.com`（华东1杭州，与现有桶一致） |
| 权限 | 私有（Private）；**禁止公共读**，防止素材泄露 |
| 生命周期 | 临时目录 7 天清理；正式资产长期保留 |

**路径规划（对象键）：**

```
/{tenantId}/{projectId}/{assetType}/{logicalKey}/v{versionNo}/{uuid}.{ext}
```

示例：
```
/u_1/p_abc123/character_image/char_hero/v1/9f3a2c1e.png
/u_1/p_abc123/shot_image/EP01-S001/v2/b8d21f4a.png
/u_1/p_abc123/shot_video/EP01-S001/v1/c7e09d12.mp4
/u_1/p_abc123/upload/cover_art/v1/5f4e2d3c.jpg
```

- 资产类型：`character_image`（角色参考图）、`shot_image`（分镜图）、`shot_video`（镜头视频）、`upload`（用户上传素材）、`final_video`（成片）、`thumbnail`（缩略图）、`temp`（临时文件）
- 缩略图路径：`/thumbnails/{storage_key}` 或同路径加 `_thumb` 后缀

### 4.3 图片存储

| 项 | 方案 |
|---|---|
| 上传 | 前端直传 OSS（预签名 URL）或后端中转（小图）；推荐**预签名直传**（大图不占服务器带宽） |
| 元数据 | 数据库 `assets` 表存 `storage_key` + `sha256` + `size_bytes` + `metadata_json`（尺寸/格式/seed/角色 ID/集/镜头 ID） |
| 缩略图 | 上传后后端生成（OSS 图片处理或本地 Pillow），存 `thumbnail_key`，列表页只加载缩略图 |
| 访问 | 预览走**短期签名 URL**（默认 30 分钟）；前端 `<img>` 直接加载签名 URL |
| 去重 | 上传校验 SHA-256，重复内容不重复存 |
| 格式 | 生成图 PNG/JPG；上传素材校验 MIME + 魔数（禁 SVG 一期） |

### 4.4 视频存储

| 项 | 方案 |
|---|---|
| 来源 | 供应商（可灵/即梦等）生成后回调 URL → 后端下载转存 OSS（私有） |
| 上传 | 后端拉取（供应商给 URL）或分片上传（用户上传大视频）；OSS 分片上传 ≥ 100MB 用 multipart |
| 元数据 | `metadata_json` 存时长、分辨率、码率、编码、大小、封面 key |
| 封面 | 视频生成后提取首帧/指定帧为封面图（ffmpeg），存 `thumbnail_key` |
| 访问 | 播放走**短期签名 URL**（视频可能大，30 分钟~2 小时按需）；**不做永久公开 URL** |
| 转码 | 一期不转码（供应商直接输出 MP4/H.264）；二期按需转码（HLS 自适应） |
| 清理 | 未选中/未锁定的草稿视频可设 30 天生命周期自动清理（需确认产品策略） |

### 4.5 预签名 URL（访问控制核心）

| 场景 | 有效期 | 说明 |
|---|---|---|
| 前端预览图 | 30 分钟 | `<img>` 加载，过期重新申请 |
| 前端播放视频 | 30 分钟~2 小时 | 按视频时长延长 |
| 供应商拉取参考图 | 任务时长 + 缓冲（最大 24 小时） | 生成任务可能排队数分钟 |
| 上传直传 | 5 分钟 | 前端拿到后立即上传 |
| 下载导出 | 1 小时 | 用户下载成品 |

- 所有签名 URL 绑定**对象键 + 操作（GET/PUT）+ 有效期**，无法越权访问其他对象
- 签名 URL 不入库、不落日志、不推送前端缓存（用户日志不得含完整签名 URL）
- 供应商回调/下载校验：域名白名单、MIME、大小、SHA-256，入库后**转存私有桶**，不依赖供应商 URL 持久可用

### 4.6 CDN / 分发

- **一期不做 CDN**（用户量小，OSS 直连华东区域延迟可接受）
- 二期若用户量大：OSS 绑定 CDN 域名，预览图/视频走 CDN 缓存，签名 URL 用 CDN 鉴权（URL 签名 + 过期）
- 静态前端部署：`drama-studio` 前端构建产物放 OSS 静态网站托管或 Nginx（参考现有 bubble-pop 部署经验）

### 4.7 生命周期规则

| 前缀 | 规则 | 说明 |
|---|---|---|
| `temp/` | 7 天过期 | 上传中/临时文件 |
| `thumbnail/` | 30 天（可重建） | 缩略图可由原图重建 |
| 正式资产 | 不设过期 | 需长期保留（视频/图片/角色卡） |
| `trash/` | 30 天 | 软删除后的回收站 |

> ⚠️ OSS 生命周期规则**前缀不能重叠**（全桶规则 + 具体前缀会 400 报错），必须逐前缀列规则。

## 5. 任务执行引擎

### 5.1 执行流程

1. 发布或临时冻结工作流快照。
2. 校验 DAG、节点配置、端口类型、门禁、额度和供应商可用性。
3. 对目标节点的祖先子图做 Kahn 拓扑排序；若有环返回 `WF_CYCLE_DETECTED`。
4. 创建 `workflow_run` 和 `node_run`；满足依赖的节点进入队列。
5. Worker 获取租约，幂等执行，写进度事件；成功后调度后继节点。
6. 遇到人工门禁时工作流保持 `WAITING_APPROVAL`，用户操作后继续。

### 5.2 队列、重试与断点续跑

- 一期用数据库任务表 + Spring `TaskExecutor`；单实例部署，SQLite 写操作串行化（WAL + busy_timeout + 重试），任务领取用事务内 UPDATE 条件更新。
- 429、408、5xx、网络超时可重试；指数退避 `min(2^attempt × 2s + jitter, 120s)`，优先遵守 `Retry-After`。
- 参数错误、鉴权失败、内容审核拒绝默认不自动重试。
- 每次供应商提交生成 `idempotency_key = nodeRunId + attemptGroup`；已拿到外部 taskId 后只轮询，不重复提交。
- 断点续跑复用"输入指纹、配置指纹和模板指纹均未变化"的成功节点；其余节点新建 attempt。
- 取消为协作式取消：停止未开始任务；运行中任务若供应商支持则取消，否则忽略结果并记 `CANCELED`。

### 5.3 进度推送

一期优先 SSE，保留 WebSocket 适配层。`GET /api/v1/runs/{runId}/events` 推送：`RUN_STATUS_CHANGED`、`NODE_STATUS_CHANGED`、`NODE_PROGRESS`、`ASSET_CREATED`、`APPROVAL_REQUIRED`、`LOG_APPENDED`。事件含单调递增 `eventId`，客户端用 `Last-Event-ID` 补拉；断线后同时调用运行详情校准。

执行接口：`POST /workflows/{id}/runs`、`POST /runs/{id}/cancel`、`POST /runs/{id}/resume`、`POST /runs/{id}/retry-failed`、`POST /nodes/{nodeId}/runs`、`GET /runs/{id}`、`GET /runs/{id}/node-runs`。

## 6. API 网关

### 6.1 统一能力协议

定义 `LlmProviderAdapter`、`ImageProviderAdapter`、`VideoProviderAdapter`，统一方法 `validateConfig`、`estimateCost`、`submit`、`query`、`cancel`、`normalizeResult`。业务执行器不得直接依赖供应商 SDK。

### 6.2 路由和治理

- 路由维度：能力、模型、健康度、成本、用户套餐、区域和内容类型。
- 鉴权：平台 Key 或用户自带 Key；Key 使用 KMS/信封加密，只在调用时解密，日志仅显示末 4 位。
- 限流：用户、供应商、模型三级令牌桶；超过限制进入延迟队列而非直接丢弃。
- 额度：提交前预占，完成后按实际结算，失败释放；视频轮询不重复扣费。
- 标准错误：`PROVIDER_RATE_LIMITED`、`PROVIDER_AUTH_FAILED`、`CONTENT_REJECTED`、`PROVIDER_TIMEOUT`、`QUOTA_INSUFFICIENT`。

### 6.3 参考图公网 URL

私有对象不得永久公开。网关为供应商生成短时签名 URL，默认 30 分钟、HTTPS、不可列目录；若供应商会延迟拉取，按任务预估时长延长并设置最大 24 小时。回调和下载校验域名白名单、MIME、大小和哈希，入库后转存私有对象存储。

管理员接口：`/admin/providers` CRUD、`/admin/providers/{id}/test`、`/admin/models`、`/admin/quotas`、`/admin/usage`。

## 9. 非功能需求（技术实现）

### 9.1 安全

- 全站 HTTPS；JWT 短时 access token，refresh token 可撤销。
- API Key 使用 KMS 或 AES-256-GCM 信封加密；数据库、日志、异常监控均不得记录明文。
- 对象存储默认私有；预签名 URL 最小有效期、绑定对象键和操作；外链防 SSRF，禁止内网 IP、重定向到内网和非 HTTPS。
- 上传校验扩展名、MIME、魔数、大小并执行恶意文件扫描；SVG 一期禁止或净化。
- 所有资源查询强制 owner/tenant 条件；管理员敏感操作记录审计。
- Prompt 和供应商响应按用户内容处理，不用于训练；制定数据保留与删除策略。

### 9.2 可靠性

- 节点提交、供应商回调、额度扣减、选择版本均具备幂等键和唯一约束。
- Worker 使用租约与心跳；实例宕机后超时任务可被重新领取。
- 外部 taskId 一旦持久化，恢复时优先查询而非重新创建。
- 目标月可用性 99.5%；供应商故障不应导致平台不可访问，任务进入延迟/失败并可恢复。
- 关键指标：队列深度、失败率、429 比例、供应商耗时、SSE 连接数、额度差异、stale 传播失败。

## 11. 节点执行细节

### 11.1 节点执行规则

- **项目设定**：缺少故事环境或类型时标记配置错误，不调用模型；按鲸剧项目设定契约要求模型输出 JSON，Schema 校验失败最多自动修复 1 次。输出：`PROJECT_STATE_JSON` 与可读 Markdown，初始 `draft`，用户通过后 `approved`。
- **剧本大纲**：注入项目设定，输出必须含 logline、world、conflict、relationships、three_act、episodes、character_timeline。集数必须与项目一致。输出：`OUTLINE_JSON` + Markdown，`draft → approved`。
- **角色卡**：每个角色输出基础设定、外貌 10 项、`lock_prompt`、禁止变化项、正/负提示词；`character_id` 在项目内稳定。输出：每个角色独立 `CHARACTER_CARD_JSON`，批次资产为 `CHARACTER_CARD_LIST`；角色卡需 approved，参考图提示词随卡审批。
- **分集剧本**：按剧型选择仿真人剧/解说剧/动态漫格式；校验集号、角色引用、目标和钩子。输出：`EPISODE_SCRIPT_MD` + 元数据 JSON，`draft → approved`。
- **分镜脚本**：每镜必须输出 `shot_id,duration,scene_id,characters,story_purpose,shot_size,composition,action,expression,dialogue_or_caption,emotion,transition`；镜头总时长与目标允许 ±15%。输出：`SHOT_CARD_LIST_JSON` + 表格预览，`draft → approved`。
- **角色参考图**：组装正负提示词并调用文生图；每个返回结果独立成版本。输出：`CHARACTER_REFERENCE_IMAGE` 多版本，初始 `draft`；必须 `selected` 后才能作为分镜图参考，允许进一步 `locked`。
- **分镜图**：按"锁定词+场景+构图+情绪+动作+画风+质量词"排序组装；不得无提示改变人物固定项。可对镜头列表批量展开为多个子任务。输出：每个 `shot_id` 的 `STORYBOARD_IMAGE` 多版本；每镜必须选定一个版本。
- **图生视频**：运行前强制检查源图 `selected` 且视频提示词已经单独 `approved`；异步提交供应商并轮询。输出：`SHOT_VIDEO` 多版本，初始 `draft`，选定后 `selected`。
